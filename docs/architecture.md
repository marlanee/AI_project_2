# 설계와 기술 선택

## 데이터와 RAG

카탈로그 1편을 하나의 텍스트로 구성하고 별도 메타데이터 컬렉션에 ID=movie_id로 upsert한다. 외부 문서는 영화 ID:문서 ID:청크 순번으로 별도 컬렉션에 저장한다. 모델·청크 설정·출처 모드·처리 버전을 컬렉션 해시에 반영해 설정을 섞지 않는다.

질문에서 검색어를 추출하고 후보 page_id를 선별한다. 후보 밖 ID를 거절하며 영화 자체 문서는 선별 결과와 길이 조건보다 우선한다. 실시간 검색이 자체 문서를 놓치면 검증된 로컬 보완 사본을 찾는다. 본문 URL·출처·수집일·영화 관계를 보존한다. 색인 성공 후에만 완료 캐시를 확정하고 실제 청크 존재도 확인한다. 검색어·본문·질문별 완료 이력은 구분해 캐시한다.

retrieve는 메타데이터 1건과 선택 영화의 외부 근거를 합치고 중복을 제거한다. generate는 작품 소개와 현실 배경 자료를 구분하고 제공 근거에 없는 주장을 보류한다. 답변 번호를 파싱해 실제 사용한 원문만 표시한다.

## 임베딩·검색 설정

로컬은 CPU 다국어 MiniLM 384차원을 사용한다. 모델의 짧은 입력 제한으로 한국어 청크 뒷부분이 잘리는 문제를 120토큰 창별 평균·정규화로 보완했다. 공개 환경은 GMS 384차원과 사전 계산/SQLite 캐시를 사용한다. 서로 다른 임베딩은 컬렉션을 분리한다.

기본 청크 1000자/중복 200자는 문맥 유지와 20% 중복의 시작값이다. 외부 Top-k 5 + 메타데이터 1건으로 컨텍스트를 제한한다. fetch_k 20과 MMR lambda 0.65는 관련성을 우선하면서 중복을 줄일 후보 폭을 준다. 동일 질문으로 유사도/MMR·청크·Top-k 변화를 비교할 수 있으며 모든 질문에 최적이라는 주장은 하지 않는다.

## PDF와 평가

NASA 원본 8쪽 중 설명 본문 2~7쪽을 쪽별로 색인한다. 표지 등 짧은 비설명 조각은 검색 후보에서 제외한다. 파일 해시·발행기관·쪽 번호를 보존하고 위키와 같은 영화 필터 아래 검색한다.

RAG 전후 비교는 같은 모델·시스템 지침·질문·대화 조건에서 근거 유무를 바꾼다. 홀짝 질문의 실행 순서를 바꾸고 성공한 응답과 근거 스냅샷을 저장해 실패 후 이어 실행할 수 있다. 정확성·출처·불확실성을 정성 비교하고 실제 사람이 채점할 수 있다.

## 추가 웹 자료

첫 답변 이후 사용자가 요청할 때만 별도 web_search를 실행한다. 완료된 도구의 실제 출처 URL과 인용 메타데이터를 대조하고 최대 5개 자료를 표시한다. 제목·원문 링크·AI 요약·선별 이유·시점을 기존 답변과 분리한다. 원래 답변이나 Chroma 근거를 바꾸지 않는다.
